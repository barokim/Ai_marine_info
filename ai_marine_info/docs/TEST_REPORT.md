# 검증 결과

최종 코드 점검: 2026-10-31. 요청한 범위에 맞춰 서버를 구동하지 않았습니다.

## 자동 검증

| 확인 | 결과 |
|---|---|
| pytest 실패·권한·지역·환경변수 사례 + 실제 loopback HTTP smoke test | 45개 통과 |
| JavaScript 내장 VM/DOM 대역 테스트 | 6개 통과 |
| `node --check app/static/app.js` | 통과 |
| 기존 대시보드 파일 SHA-256 대조 | 참조 파일 11개 일치 |
| Supabase·해양 API 실제 호출 | 수행하지 않음 |
| 운영용 uvicorn 서버 | 실행하지 않음 |
| 임시 loopback uvicorn | smoke test 중 시작 후 자동 종료 |

pytest는 FastAPI TestClient와 Supabase SDK를 모의 HTTP 응답으로 검사하고, 별도 사례에서는 임시 loopback 포트로 실제 uvicorn HTTP 서버를 켰다 닫습니다. 실제 서버 smoke test에는 임시 폴더의 SQLite를 사용합니다. 외부 네트워크 호출은 하지 않습니다. 지역별 해양 조회 함수도 테스트 지점 데이터로 교체하며, 공식 조석·관측 파서에는 선택 지역과 다른 관측소 이름이 거절되는지를 별도 검사합니다.

## 확인된 시나리오

- 홈·물때·해양 예보·로그인·가입·비밀번호 재설정·게시판 화면이 HTML 응답을 반환합니다.
- Bearer 토큰이 없으면 게시판의 목록·상세·작성·수정·삭제 API가 401을 반환합니다.
- 올바르지 않은 토큰은 직접 디코딩하지 않고 Auth의 `get_user` 검증 요청을 거칩니다.
- 가입 이름은 Auth 사용자 메타데이터에 전달되고 로그인 응답은 refresh token 없이 반환됩니다.
- 이메일 확인과 비밀번호 재설정 코드는 URL이 아닌 요청 본문으로 전달됩니다. 재설정 후 새 비밀번호로 로그인하고 이전 비밀번호가 거부되는 부분은 모의 Auth 응답으로 확인했습니다.
- 같은 게시글을 다른 회원이 수정·삭제하면 404이며, 요청 본문으로 `author_id`를 주입하면 422입니다. PostgREST 요청에는 해당 회원의 Bearer 토큰이 붙습니다.
- 두 사용자의 관찰 기록·조회 이력·사진이 서로 보이지 않는지 임시 SQLite로 검사했습니다.
- 관측소가 없는 지역은 실측 자료 없음으로 표시하고 다른 지역 지점은 명시적으로 선택해야 합니다. 기존 인천·부산·제주 별칭도 검사했습니다.
- MBRIS와 사진 처리 함수는 기존 구현을 호출하도록 연결하고, 사진에는 인증과 동의를 요구합니다.
- 잘못된 publishable key·HTTP Project URL, 과도한 인증 요청, 다른 Origin 요청이 제한됩니다.
- `.env.example`의 비밀값 변수들이 비어 있고 `.env`가 Git 제외 목록에 있는지 검사합니다.
- 짧은 비밀번호·잘못된 이메일·공백 이름·작성자 위조 필드, 게시글 제목/내용 길이 위반, 조합이 틀린 시·도/시·군·구, 모르는 지점 코드, 기존 `region`과 새 `city_id` 동시 입력, 잘못된 게시글 UUID를 각각 거절합니다.
- 임시 loopback 서버에서 실제 HTTP로 홈페이지 200, 전국 지역 JSON(74개), 비로그인 게시판 401, 64 KiB 초과 인증 요청 413을 확인한 뒤 서버가 자동 종료됐습니다.
- 게시글에 HTML 문자열을 넣었을 때 태그가 실행 요소가 아닌 텍스트로 렌더링되는지 확인했습니다.
- Supabase API/SMTP/SQL 실행, 실제 RLS 강제, 실제 계정 A·B, 실제 메일 수신 및 비밀번호 변경, KHOA·MBRIS·OpenAI 인증은 확인하지 않았습니다. 이는 사용자 Supabase 프로젝트와 실제 API 키 설정 후 별도 확인해야 합니다.

## 테스트 환경 참고

 pytest 실행 결과는 **45 passed**이며 Starlette의 `httpx` TestClient 사용 중단 예정 경고 1건이 출력됩니다. 테스트는 현재 SDK 조합에서 통과합니다. 개발 패키지 설치 명령은 `python -m pip install -r requirements-dev.txt`입니다.
