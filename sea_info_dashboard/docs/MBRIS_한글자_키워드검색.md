# MBRIS 한 글자·키워드 포함 검색 수정

2026-10-30, 사용자가 실행 중인 `http://127.0.0.1:8000/`에서 확인했다.

## 원인

- MBRIS 전용 `/api/mbris/species?q=바지락`은 이미 정상 수신 중이었다. 따라서 실제 서비스 연결 자체는 정상이다.
- 기존 `/api/species?q=바지락`은 WoRMS만 호출했다. API 문서에서 이 주소를 실행하면 화면과 다른 출처가 나왔다.
- 검색 함수 내부 검사를 1글자로 바꿔도 FastAPI의 `Query(min_length=2)`가 남아 있어 `김`은 함수 실행 전에 422로 거절됐다. HTML 입력란에도 `minlength="2"`가 있었다.
- MBRIS에서 첫 20건만 가져오고 `totalCount`를 버려 다음 결과를 볼 수 없었다.

## 변경 흐름

```text
검색창 또는 API 문서 → /api/species?q=김&provider=auto&page=1
  ├─ 한글: MBRIS CommKorNm 포함 검색
  └─ 학명·영문명: 기존 WoRMS 검색
```

`provider=mbris`와 `provider=worms`로 직접 선택할 수도 있다. 기존 MBRIS 전용 경로는 유지했다. 키가 없을 때 다른 제공자로 조용히 바꾸지 않고 503과 설정 안내를 반환한다.

## 수정 위치

- `main.py`: 통합 검색의 출처 선택, 검색어 최소 길이 1, 페이지 번호, 앱 버전 0.3.0.
- `services.py`: `get_mbris_page()`에서 pageNo·numOfRows를 전달하고 totalCount를 읽는다. 기존 `search_mbris()`는 학습용 첫 페이지 목록 함수로 유지한다.
- `models.py`: MBRIS 응답에 페이지 번호·전체 건수·다음 페이지 유무를 추가한다.
- `species_service.py`: WoRMS 검색 함수의 최소 길이도 1로 맞춘다.
- `static/index.html`: 한 글자 입력 허용, 검색 출처 선택란·이전/다음 버튼, JS 버전 쿼리 추가.
- `static/app.js`: 통합 API 호출과 MBRIS 페이지 이동, 실제 출처 표시.

키워드 포함 검색은 입력 문자열이 국명에 포함된 결과를 뜻한다. 오타 교정이나 초성 검색을 구현한 것은 아니다. 예를 들어 `김`은 김류 외에도 이름에 `김`이 들어간 다른 생물을 포함할 수 있다.

## 실제 검증

브라우저에서 `김`을 입력하고 검색해 총 28건을 확인했다. 1페이지는 20건, 2페이지는 나머지 8건이었다. 2페이지에서 `방사무늬돌김`(`Neopyropia yezoensis`) 등의 결과를 확인했다. 이것은 검증 시점의 제공자 응답이며 향후 갱신될 수 있다.

자동 테스트 35개 및 JavaScript 구문 검사 통과. 한 글자 검색, 자동 MBRIS 선택, 명시적인 출처 선택, 페이지 전달·전체 건수, 키 누락 시 WoRMS로 바꾸지 않는 동작을 검증했다. 기존 관찰 기록 제목의 최소 길이 2는 생물 검색과 별도 규칙으로 유지했다.

브라우저에서 이전 화면이 보이면 Ctrl+F5로 새로고침한다. `/api/status`에서 `app_version=0.3.0`, `mbris_configured=true`를 확인하고 검색 출처를 자동 또는 MBRIS로 선택한다.

로컬 서버는 원래 실행 중인 서버를 사용했으며 별도 서버를 새로 시작하거나 종료하지 않았다. GitHub에는 아직 이전 검색 코드가 있어 Render에 반영하려면 관련 파일을 함께 커밋하고 재배포해야 한다.
